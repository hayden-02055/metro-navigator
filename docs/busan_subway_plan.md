# 부산 도시철도 역간 이동 경로 탐색 — 과제 계획서

---

## 1. 과제 개요

| 항목 | 내용 |
|------|------|
| 주제 | 부산 도시철도 역간 이동 경로 탐색 |
| 사용 언어 | Python |
| 대상 노선 | 부산 도시철도 1~4호선 + 부산김해경전철 + 동해선 광역전철 |
| 제출물 | 코드 파일 + 보고서 |

---

## 2. 주제 선정 이유

- 1~4호선, 적당한 역 수 → 그래프 구조 학습에 최적
- 서울 대비 환승역이 단순하여 자료구조 로직에 집중 가능
- 실제 지하철 데이터를 활용하므로 현실감 있는 결과 확인 가능

---

## 3. 자료구조 설계

### 3-1. 그래프 표현 방식 비교

그래프를 표현하는 방법은 크게 세 가지가 있다.

**① 인접 행렬 (Adjacency Matrix)**

```python
#        남포  중앙  부산역
matrix = [
# 남포  [  0,   2,    0  ],
# 중앙  [  2,   0,    2  ],
# 부산역[  0,   2,    0  ],
]
```

- 두 역의 연결 여부를 O(1)로 확인 가능
- 역 수 N에 대해 N²만큼의 공간 필요 → 역이 많을수록 공간 낭비 심함

**② 인접 리스트 (Adjacency List)**

```python
graph = {
    "남포": [("자갈치", 2, "1호선"), ("중앙", 2, "1호선")],
    "서면": [("범내골", 2, "1호선"), ("부전", 2, "1호선"), ("전포", 2, "2호선")],
}
```

- 실제 연결된 역만 저장 → 공간 효율적
- 희소 그래프(Sparse Graph)에 적합

**③ 엣지 리스트 (Edge List)**

```python
edges = [
    ("남포", "중앙", 2, "1호선"),
    ("중앙", "부산역", 2, "1호선"),
]
```

- 구조가 단순하여 이해하기 쉬움
- 특정 역의 이웃을 찾으려면 전체 리스트를 순회해야 함 → 탐색 비효율

---

### 3-2. 선택: 인접 리스트

| 방식 | 공간 복잡도 | 이웃 탐색 | 희소 그래프 적합성 |
|------|------------|-----------|------------------|
| 인접 행렬 | O(N²) | O(1) | ✗ |
| **인접 리스트** | **O(N + E)** | **O(degree)** | **✓** |
| 엣지 리스트 | O(E) | O(E) | △ |

부산 지하철은 역 수(N) 대비 연결(E)이 훨씬 적은 **희소 그래프**이므로 인접 리스트가 가장 적합하다. 인접 행렬로 구현할 경우 100개 이상의 역에 대해 100×100 크기의 행렬이 필요하지만, 실제 연결은 각 역당 2~4개에 불과하다.

---

### 3-3. 그래프 구성 요소

| 구성 요소 | 내용 |
|-----------|------|
| 노드 | 각 지하철 역 |
| 에지 | 인접한 두 역 사이의 연결 |
| 가중치 | 역간 소요시간 (분 단위) |
| 환승 에지 | 같은 물리적 역이지만 노선이 다를 경우 별도 에지로 연결 (소요시간 +3분) |

## 4. 알고리즘 선택 및 이유

| 알고리즘 | 탐색 목표 | 선택 이유 |
|----------|-----------|-----------|
| BFS | 최소 환승 경로 | 가중치를 무시하고 환승 횟수(레벨)를 최소화하는 데 적합 |
| 다익스트라 + PQ | 최단 시간 경로 | 역간 소요시간 가중치를 반영한 최단 경로 탐색에 적합 |

두 알고리즘을 동시에 실행하여 결과를 비교 출력한다.
최소 환승 경로와 최단 시간 경로가 항상 일치하지 않을 수 있음을 보여준다.

---

### 4-1. 다익스트라 기본 동작

1. 출발역 거리 = 0, 나머지 모든 역 거리 = ∞ 로 초기화
2. 아직 확정되지 않은 역 중 거리가 가장 짧은 역을 선택
3. 해당 역의 이웃 역들에 대해 거리를 갱신
4. 도착역이 확정될 때까지 2~3 반복

### 4-2. Priority Queue로 발전시킨 이유

기본 다익스트라는 "거리가 가장 짧은 역을 선택"하는 과정에서 **매번 전체 역을 순회**한다. 역이 N개일 때 이 과정만 O(N²)이 걸린다.

여기서 **Priority Queue(우선순위 큐)** 를 도입하면:

| | 기본 다익스트라 | PQ 기반 다익스트라 |
|---|---|---|
| 최솟값 선택 | O(N) — 전체 순회 | O(log N) — 힙에서 바로 추출 |
| 전체 시간 복잡도 | O(N²) | O((N + E) log N) |
| 역 100개 기준 | 10,000번 연산 | 약 700번 연산 |

PQ는 항상 **소요시간이 가장 짧은 역을 먼저 꺼내주는 자료구조**이기 때문에, 매번 전체를 뒤질 필요 없이 바로 다음 확정 역을 알 수 있다. Python에서는 `heapq` 모듈로 구현한다.

```python
import heapq

# (소요시간, 역이름) 형태로 힙에 삽입
heap = [(0, "남포")]

while heap:
    time, station = heapq.heappop(heap)  # 가장 짧은 시간의 역 추출
    ...
    heapq.heappush(heap, (new_time, next_station))  # 이웃 역 삽입
```

즉, 다익스트라 알고리즘을 **Priority Queue로 구현함으로써 기본 방식 대비 성능을 개선**한 것이 이번 과제의 핵심 발전 포인트다.

## 5. 구현 단계

```
Step 1. 데이터 정의
        └─ 1~4호선 역 목록 정의
        └─ 역간 소요시간(분) 정의

Step 2. 그래프 구축
        └─ 인접 리스트 생성
        └─ 환승역 에지 추가

Step 3. BFS 구현
        └─ 최소 환승 경로 탐색

Step 4. 다익스트라 구현
        └─ 최단 시간 경로 탐색

Step 5. 결과 출력
        └─ 경로, 환승 횟수, 소요시간 출력
        └─ 두 알고리즘 결과 비교 출력

Step 6. 테스트
        └─ 다양한 출발/도착 케이스 검증
```
