# Spec v1: 부산 도시철도 경로 탐색 — 데이터 정합성 수정

> **버전**: spec_1 (spec_0 기반 수정판)
> **변경 유형**: fix (데이터 오류 수정) + chore (빌드 스크립트 추가, 문서 정정)
> **코드 변경 없음**: `busan_subway.py`의 알고리즘·클래스 구조는 v0 그대로 유지한다.

---

## 1. 변경 배경

v0 데이터(`busan_metro.csv` → `metro_data.py`)가 실제 부산 도시철도 노선과 다르게 손상되어 있음이 확인되었다. 역 삽입·누락·순서 오류·오타가 4개 노선에 걸쳐 존재하며, 이로 인해 탐색 결과 경로가 현실과 다르게 출력된다.

근본 원인: **데이터 검증 게이트 부재.** CSV 생성 후 "알려진 경로와 대조" 단계 없이 그래프 변환 → 결과 출력까지 그대로 통과했다. v1은 데이터 수정과 함께 검증 단계를 워크플로에 명시적으로 추가한다.

## 3. 노선별 오류 상세와 수정안

| 오류 | 수정 |

## 5. 신규 컴포넌트: `build_graph.py` (C8)

v0에는 CSV → `metro_data.py` 생성기가 없어 데이터 수정 시 640줄을 수작업해야 한다. 생성기를 추가해 "CSV = 단일 진실 공급원"을 실제로 성립시킨다.

### 입출력

```
입력:  data/busan_metro.csv   (line, order, station, transfer)
출력:  src/metro_data.py      (GRAPH 인접 리스트, 자동 생성 헤더 포함)
실행:  python3 build_graph.py
```

### 생성 규칙

1. 같은 노선의 연속(order) 역 사이에 양방향 에지 `(이웃역, 2, 노선명)` 추가
2. `transfer` 컬럼에 표시된 역은 노선 간 **단일 노드로 병합** (예: 서면)
3. 환승 표시 없이 역명이 충돌하면 `역명(노선)` 접미사로 자동 분리 (예: 좌천)
4. 출력 파일 상단에 `# AUTO-GENERATED by build_graph.py — 직접 수정 금지` 주석 삽입

### 내장 검증 (생성 실패 조건)

- 노선별 역 수가 §4-1 표와 불일치하면 에러
- 모든 에지의 대칭성 검사 (A→B 있으면 B→A 존재)
- 접미사 처리 후에도 남는 이름 충돌이 있으면 에러
- 종료 시 총 노드 수 출력 → 기대값과 수동 대조 (수식: 노선 합계 − 병합 환승역 수)

### 제약

- 표준 라이브러리만 사용 (`csv`, `collections`) — 과제 제약 유지
- 제출물 실행에는 불필요 (개발 도구), 단 보고서에 "재현 가능성" 포인트로 기술
